# Decision geometry at SLIC

Adapted from the owner's *THE BOOK: Design Scripture*, *Design Principles:
No MSH, No Slop, Real Balance*, and *Ultimate Design System Canon*. These
are design references, not a replacement for project rules or a mandate to
apply decorative diagonals, rewrite the palette, or collapse long-form prose.

1. Name the decision and the reading order. On Rankings: what the workbench
   does, the weight controls and spider together, then the results and their
   publication note. On map routes, start with the map; use the edge for
   controls and keep the source next to the claim.
2. Name the grid. Rankings uses the workbench's left axis for the introduction,
   a second desktop column for the spider, and one stacked phone column.
   The three figures fit on one ruled strip. They do not need three cards.
3. Measure the cost of acting. Record the first useful control's distance from
   the top, masthead height, chart entry, avoidable wraps and gaps. Compare the
   same route, state and viewport. Capture 390, 1024 and 1440, plus 320 and
   enlarged text for overflow and access. Have someone other than the builder
   check the screenshots for hierarchy and balance.
4. Preserve the instrument and its evidence. Do not reduce readable type or
   tap targets, clip qualifiers, delete charts, or mistake all document depth
   for waste. Keep released scores separate from exploratory scores and
   historical traffic records separate from new session totals.

## Rankings regression budget

`npm run check:shipability` requires the first preset to be fully visible in
the first 55% of the viewport, and the chart frame to start within the first
80% on phone or 55% at desktop/tablet. It also opens all results and compares
every baseline row's score, rank and tier to the publication, switches to a
custom preset, then verifies the published rows again on reset.

| Viewport | First preset top, old to new | Reduction |
| --- | ---: | ---: |
| 390 × 844 | 868 px to 363 px | 58% |
| 1024 × 768 | 625 px to 298 px | 52% |
| 1440 × 900 | 657 px to 318 px | 52% |

These are English Chromium measurements, comparing the November 12 live
baseline with the candidate. The previous page fails the new control budget
at each width; this is not a claim about all routes or total document height.
The disclosure remains in the workbench after the published results it
describes, and does not appear in exploratory profile-fit mode.

The existing release gates still apply. The 55% and 80% bounds measure where
this particular instrument starts; they are not a proxy for map coverage,
locale quality, accessibility, or independent visual review.
